# 记账统计

本插件只读取指定文件夹中的每日记账 Markdown，正文逐笔记录是唯一统计来源；frontmatter `total` 只参与核对，`.base` 与 `.duowei` 不会计入。

## 安装与使用

当前目录已经是可安装的 Obsidian 插件目录。构建后确保 `main.js`、`manifest.json`、`styles.css` 位于 `.obsidian/plugins/ledger-statistics/`，然后在“设置 → 第三方插件”中启用“记账统计”。使用左侧栏饼图图标或命令“打开记账统计”进入。

也可以从 GitHub Releases 下载最新的 `ledger-statistics-v*.zip`，解压到 Vault 的 `.obsidian/plugins/ledger-statistics/` 目录后启用插件。

默认打开总览；可在设置中选择首次打开时使用今天、本周、本月、工资日或今年。顶部筛选在六个视图间保留；本周按周一开始，当前周截止今天。工资日按每月15日至下月14日计算，当前周期截止今天。时间选择器旁的两个图标按钮会按照当前时间类型切换日期、周、月、工资周期或年份；自定义期间不启用周期切换。点击指标、图表、分类行或日期会进入对应明细。默认“消费支出”会排除设置中配置的 `债务/还款`，切换到“全部支出”可纳入。排除后的结果只是配置口径，并不代表已经人工核实的真实消费额。日均的分母是所选范围内实际存在日记账文件的日期数，缺少文件的日期不按零消费处理；有文件但当前口径金额为零的日期仍进入分母。

设置中的“每日预算”用于总览的“今日预算”液体进度条。预算卡片固定统计本地今天的支出，不受总览的日期、分类和关键词筛选影响；“预算分类”默认统计全部分类，包括 `债务/还款`，选择具体分类后只统计该分类。“今日预算星标口径”可以选择包含或排除星标支出，并统一作用于今日已花、当前工资周期支出和 Bark 提醒。预算金额下方会按31天估算月支出，并显示从本月15日至今天的当前工资周期支出；预算未设置时显示提示，超出预算时显示超支金额。填写“Bark 推送地址”后，当前预算口径首次达到或超过预算时会发送一次提醒，每个自然日最多一次；地址只保存在本地设置中。

总览顶部的“洞察”使用设置中的“每个工资周期到账工资”；未校准时，“目前还剩”是工资减本周期全部已记账支出的账面推算值。设置 → 余额校准中可以填写此刻的实际余额，此后新发生并入账的消费会继续扣减。工资和当前余额分别保存，设置页显示“未记账净差额＝工资－本周期已记账支出－当前余额”；正数表示实际余额比账面推算少，负数表示实际余额比账面推算多，差额不等同于垫付。校准前已发生、后来补记的消费只会减少未记账净差额，不会从实际余额重复扣款；新工资周期不沿用旧校准，未入账资金变化需再次校准。程序仍以原始记账支出比较当前与前两个完整工资周期，扫描全部消费分类并生成工资压力、金额异常、消费频率、笔均金额、大额单笔和消费结构变化等候选事件；余额校准及差额不参与候选事件、历史均值或 AI 判断。分类参考余量来自可用完整周期的平均值，只用于参照，不等同于预算。移动端的周期数据与分类参考默认折叠，可自行展开。

历史同期平均笔数保留小数，例如两个周期分别有 2 笔和 3 笔时，平均为 2.5 笔。历史笔均金额使用可用历史同期的总金额除以总笔数，最后取整到分，避免笔数取整导致单次花费或消费频率误报。

今日洞察每天按设备本地日期更新，主卡片区分预算内、接近预算、超预算、未设置预算、明确零消费、未记录及账目待核对；预算金额、分类与星标口径和“今日预算”一致，总金额仍显示当天全部已解析支出，不受顶部历史筛选影响。今天未创建账本仅提示“暂未记录消费”，不认定正常或零消费。周期历史参考仍将记账起始后的未记账日按零消费参与统计；补记后自动重算并使旧 AI 缓存失效。此规则适用于当前工资周期，以及最早已知记账日期之后的历史日期，不把开始记账以前的月份虚构成完整零消费周期。已有文件解析失败、日期或总额核对异常时仍需核对，不会用零消费覆盖错误。只有一个可用历史周期时只使用该周期，不除以二；不足两个历史周期或当前周期存在异常账本时暂停消费异常比较。周期末参考采用“本周期已花＋历史周期相同已过天数之后的平均支出”，周期初七天内或仅一个历史周期时标注低置信度；没有完整历史或当前账目核验失败时不显示预测。此方法不会将月初固定支出按日均倍增，但付款日期变化仍会影响参考值。点击 AI 判断卡片右上角的圆形感叹号，可查看判断依据、固定支出与统计口径，并打开异常账本；再次点击或按 Esc 收起。本次变更只调整洞察口径，不改变其他统计页明确标注的“有日记账文件日期”日均分母。

主卡片展示“今日洞察”，跨天及账目、预算或统计依据变化后立即撤下过期 AI 文案，先展示程序生成的今日简报，再在卡片可见时自动更新 AI。首次启用也会自动生成，连续修改防抖 1.5 秒；自动调用可能产生模型费用。同一批数据请求失败后不反复自动重试，可手动刷新；手动刷新允许在数据不变时重新生成，且只更新洞察区域。仍成立的周期异常单独放在默认收起的“仍需关注”中，已不成立的异常退出提醒，不再霸占每日主卡片。今日简报无需设置工资；工资仍用于余额和周期参考。

星标使用交易内容及重复次数关联，插入空行或其他交易不会转移星标，插件运行期间重命名文件或文件夹会同步关联。升级时按当前账本迁移旧行号星标；无法找到的旧关联保留为未解析状态。修改被标记交易的金额、时间、分类、备注，或改变完全相同记录的数量后，需要通过“核对星标”重新关联，以免关联到错误记录。旧版已经发生的星标错位无法自动还原；插件未运行期间重命名文件也需要手动核对关联。

“AI 财务判断”是可选功能。启用后填写兼容 OpenAI Chat Completions 的接口地址、模型名称和 API Key。程序先计算周期汇总、分类参考、候选事件和共享证据目录，AI 围绕当天简报解释数据，将仍有效的周期异常作为背景；有异常证据时可推测可能的生活场景或消费行为原因，并生成针对原因假设的行动建议及最多三个相关分类意见。原因必须明确表达不确定性；交易备注已经说明用途时，不会再要求核实用途或判定固定、偶发。涉及季节的推断会收到按当前周期日期动态生成的月份和北半球常规季节，只用于排除明显时间错位，不代表具体地区天气。每条 AI 判断必须引用程序提供的有效证据；多个候选共享同一证据时只发送一次并通过 ID 引用，避免重复发送和重复放大。同一分类的相关变化会归入同组理解。AI 可自然引用数字、日期、金额、比例和笔数；程序提供 numeric_facts，校验结构化 fact_claims 与关键数量引用，发现不一致时回退本地简报。建议中的数字目标须明确标为假设，不当成已记录事实；这些校验降低错误风险，并不能保证自由文本绝无误解。为帮助 AI 区分一次性支出、重复购买和消费用途，插件只会为相关异常候选发送有限交易样本：单笔异常发送该笔备注，分类异常最多发送三至五笔代表交易，工资压力最多发送三笔主要支出；不发送账本文件、文件路径或完整原始行。备注被明确标记为不可信账目数据，只能作为用途线索，不能作为模型指令。返回无效、请求失败或功能未配置时，卡片继续显示当前日期的本地简报，不把昨日 AI 文案当成今天的分析。MiMo 请求关闭不必要的深度思考，AI 请求最长等待 60 秒；超时或关闭页面后废弃结果，关闭前尚未发出的请求会取消。Obsidian 原生请求无法强制中断，因此连接尚未结束时保持请求锁，防止再次点击产生重叠请求；连接结束后可重试。

插件开启时，预算提醒随账目更新、设置变化及定时检查运行，无须打开总览。Bark 仅在 HTTP 成功且返回 `code: 200`、`message: success` 后记为当天已提醒；失败会留出五分钟重试间隔。Obsidian 被关闭或手机系统挂起期间不保证后台运行。回到前台及跨日检查会更新当前日期预设；手动选择的历史范围与自定义范围保持不变。账目读取使用文件版本检查及有上限的并发，整文件夹移动和删除会更新子文件缓存，迟到的旧读取不会覆盖新记录。

总览底部会显示“星标大额支出”面板。它不会自动按金额判断，而是汇总顶部所选时间范围内、由你在明细中手动标记为星标的记录；桌面端可右键记录，移动端可长按记录，在菜单中选择“标记为星标”。星标状态保存在插件本地设置中，不会修改原始 Markdown 账目。

## 洞察与固定支出确认

- 工资日固定每月 15 日。未校准时的账面余额仅为到账工资减本周期全部账目支出；校准后，洞察顶部以手动输入的实际余额为起点继续跟踪新记账消费。余额校准不改动工资、原始账目或 AI 判断依据。
- 今日简报每天更新；仍有效的周期异常保留在默认收起的提醒区，已不成立时撤下。生成时间留在卡片上，已有异常阅读历史最多保存 200 条事件标识和指标，不含原始消费备注；缓存使用相关交易样本的短指纹，不额外保存备注原文。
- 本地程序负责金额、周期、候选事件和证据；AI 负责从已确认的异常结果推测可能原因并给出克制、可验证的建议。原因假设不等于事实；关键金额由程序展示并供 AI 引用核验，AI 不得编造财务事实。
- 设置 → 固定支出 → 管理固定支出：填写名称、预计金额，并确认本周期以及前两个周期是否支付。已支付须关联实际账目；本周期未支付可选择“尚未支付”，没有该项支出需明确选“此周期无需支付”。每笔账目只能用于一个固定项目，分期请拆项。未填写名称或金额的草稿不参与计算。
- 调整后周期末参考＝本周期已花＋历史剩余阶段平均（减去其中明确关联的固定项）＋本周期确认未支付的固定项。原始账目和实际余额不会因规则而改变；只有完整历史周期参与平均。支付状态未知、关联失效或重复使用账目时暂停预测并提示核对。进入新工资周期后需重新确认，不擅自假定已付或未付。
- 设置中的“测试 AI 连接”只发送简短测试消息，区分认证、接口/模型、限额、网络和超时问题；可能产生少量模型费用，与正式判断共享请求锁。
- 失效星标会出现核对提示；可在提示或设置中重新关联账目、移除单个星标，不修改源笔记。

## Lieflat Charts 视觉体系

界面采用纸张灰、墨黑与七级灰阶构成的单色系统，保留宽圆角卡片、细线图形、结论式标题和明确来源行。分类条形图、环形图、趋势折线/面积图和对比图分别基于 Lieflat Charts 的 F5、F4、F2/F3、F12 图形语法实现，并针对 Obsidian 的点击下钻、中文标签、深色主题和移动端触摸操作进行了适配。所有图形均由插件本地生成 SVG，不加载 Lieflat 页面或任何远程资源。

总览的工资周期瀑布图基于 F9：从设置中的周期工资出发，各分类只扣除当前工资周期已经入账的支出，顶部“已支出”也只统计这些记录，不受顶部筛选影响。启用余额校准时，分类支出后单独列出正负“余额校准差额”，末项显示与洞察卡片一致的“实际余额”；差额仅用于对账，不算新的消费，不进入分类和 AI 判断。未校准时末项仍是“账面剩余”。已入账的固定支出不会再次扣除。点击单个分类会带着该工资周期进入明细。在单分类、无关键词且所选期间不超过 35 天的明细页，若此前两个已结束工资周期至少有 8 笔该分类交易，会基于 F15 显示历史单笔金额箱线图，并以橙点标出所选期间最大单笔；样本不足时不绘制。箱线图只比较分类金额，不能将混合用途的类别自动解释为同一消费行为。移动端瀑布图使用逐级余额卡片，箱线图另有窄屏图形和可点击的数值摘要。

## 移动端

- 筛选区默认收起为一行摘要，点击后展开；当前日期、口径和分类无需展开即可确认。
- 开始与结束日期合并在同一个双列日期组中，七个视图入口保持单行可见。
- 总览指标使用 2×2 卡片布局；分类刻线、趋势图和期间对比使用独立的移动端图形，不再按比例缩小桌面 SVG。
- 较长趋势图支持横向触摸滚动，明细使用卡片列表，日历使用逐日单列列表。
- 所有主要控件保持至少 44px 的触摸高度；手机端不依赖悬停交互。
- 从图表、分类或日历下钻到明细时会保留原筛选条件；点击明细顶部的“返回上一级”即可回到原本月或原期间。
- 明细卡片的“打开来源”固定在卡片底部操作区，避免与备注内容混排。
- 移动端滑到底后停留；从底部重新上拉时显示进度，拉动约 100px 后提示“松手切换”。松手才进入下一个视图，未达到阈值或收回手势则回弹取消。最后一个视图不循环跳转。

## 支出报告（2.9.1）

导航最后的“支出报告”默认分析当前工资周期（每月15日至次月14日）截至今天的流水，和上一工资周期相同已过天数比较；已结束周期比较完整周期。可切换自然月、自定义期间以及上一期、下一期。报告筛选独立保存，分类、关键词、支出口径和星标同时作用于本期与历史。周期天数不同时，金额、笔数和出现天数均按观察日折算，保留上期原始值；最多查看六个历史完整期间。

程序先从备注明确词语及同义写法识别消费对象，再计算金额与笔数分解、金额分布、大额贡献、重复购买、星期节奏、趋势、类别结构和按星期匹配的同日关联。品牌不擅自等同于商品；混合购物不分摊未知金额，多标签证据不重复计数。对象规则可在设置中以“标签=正则 / @品牌=正则”配置，默认涵盖外卖、打车、地铁公交等用途。未知备注规范化标点及明确数量，不删除型号数字、不将任意前缀当作同义词。报告最多五个发现，同主题及高流水重合度的品牌/对象线索合并；“查看依据”可打开数值、期间、解释限制和相关流水，“查看本期概况”提供独立总量证据。

筛选规则集中在 `src/report-config.ts`，不是置信概率。频次候选通常要求折算差至少四笔、每天频次变化至少20%；金额差至少100元且变化至少20%；降级缺失比较使用30%的相对门槛。分布候选要求两期各至少十笔，金额档位按两期合并分位数确定；基础分布证据不依赖候选门槛。持续记录至少跨最近四个完整周中的三周；趋势至少八个完整周，前后至少四周，绝对周频次差至少两笔且满足相对变化与稳健斜率。支持周末、工作日和单日重复高峰。补充完整历史期日均中位数/MAD基线（至少三期）和分类历史P90大额线索。各类型分数统一尺度，有时间线索时对比主类型最多三席，并保证至少保留一组时间证据。

关联要求不同流水共同出现，比较两个方向并只保留一条；采用按星期固定出现频率的精确尾概率作探索筛选，并按实际候选对数校正（0.05 / 对数），另要求至少八周、对象各出现十天、共同出现五天及匹配比例至少两倍。日期连续依赖及其他情境未完全控制，此结果仍只是关联线索，不是因果或“分析可信概率”。普通三餐仅重复出现不单独列为发现；筆数不是数量，每笔金额不是商品单价。

报告使用独立的数据完整性口径：缺失账本视为未知，明确零消费才按零；日期、解析和合计异常需核对。进行中周期最多截去连续末尾两天缺失，显示实际截止并同步缩短上期同期。最多一个中间缺失日且不超过自然日5%时可降级比较，只描述已观察日期，不推断完整总额；异常账本、起止缺失或更大缺口仍暂停两期比较。完整周逐周核验，不依赖整个月完整，最多回退一个完整周并注明范围。历史不足或没有可靠发现时不硬凑结论；只使用日期，不作小时级順序分析。

进入页面仅计算本地分析；“生成报告”手动调用已启用的AI接口，复用现有接口、模型及请求锁。AI收到已记录流水汇总、发现、计算事实和每个发现最多五条用途备注样本，不发送账本文件、路径或原始行。备注是不可执行的不可信数据。2.8.2 起删除支出报告的全部AI内容校验：数字、日期、发现ID、证据ID、格式、段落数量和文字长度均不再阻断报告，也不显示数字校验提示。JSON能识别时按段落排版，普通文字、Markdown或其他结构保留返回内容。可对应的本地证据可直接打开，缺少关联时提供独立的“本地分析与证据”入口，不猜测未知ID的指向。本地没有候选发现时也可手动请求AI。仅网络或接口请求失败时保留本地分析，不自动重试；程序数据与AI自然语言解释是不同来源。

最近六份AI报告缓存在插件本地设置中，不额外保存备注原文。跨天更新当前周期截止日；补记、修改、删除、重命名、筛选或模型配置变化后，依据指纹不匹配的旧报告不会作为当前分析显示。选定的历史期间跨工资日仍保持原范围；离开报告页、关闭视图或依据变化时废弃未完成请求结果。报告不依赖工资金额，也不将余额校准差额计入消费。

2.9.0 的规则版本、全部阈值和对象词典进入指纹；旧AI报告自动失效，需要手动生成新报告，不会自动调用接口。本地报告直接显示概况及关键数字，不依赖AI；解析后的账本按日期建索引，同日重绘按仓库内容修订号复用本地快照，数据、筛选、词典及日期变化立即重新计算。默认阈值经过当前账本回放、缺失敏感性及随机对照检查，但未拥有行为真值标签，也不宣称对其他用户或未来月份最优。

2.9.1 补齐全账本基础证据：两期各自最贵三笔、扣除后的其余金额、P25/P75/P90、统一金额档位和完整分类增减，不需要先触发候选发现。两期长短不同时，差额、档位笔数和分类增减沿用观察日折算并保留原始值。总差额为零不计算差额比例，负比例及超过100%的比例保留为金额抵消线索；它们不是概率。无记录时不将均值、中位数和分位数填成零。数据不可比时只提供原始值，不生成增减及新增分类判断。

证据明确标注分析对象、期间和筛选，附观察线索、相反线索及解释限制，并一起提供给AI。中位数上涨不能排除大额影响；次数/平均每笔的分解仅是计算关系，不表示每笔都变贵或商品涨价。弹窗将概况分组，默认展开总量与最贵记录，其余指标可展开查看；全部分类逐一保留。正文只打开明确提供的有效证据ID，不再从发现ID自动推导引用。无有效引用时保留完整正文并展示独立本地分析，部分未知引用只显示可对应的证据；引用对象显示在段落下面，不把链接当作判断已获证明。规则版本升级为3，旧AI报告需手动重新生成，仍不恢复AI正文拦截。

2.8.3 起自动修复报告JSON中的未转义引号、换行、缺失括号和代码围栏，并解析重复编码的JSON，避免将报告结构作为一大段代码显示。此前缓存为原文的报告会在本地重新排版，保留生成时间，无需重新调用AI；普通文字及无法恢复的响应仍保留，不恢复内容拦截。

2.8.4 起标题下显示周期进度及比较口径，区分进行中、历史完整周期和上期天数不足。报告金额显示两位小数、百分比一位小数，明确的增加值用 `+` 和红色、减少值用 `−` 和绿色；证据弹窗沿用相同格式。正文支持空行分段和 `**重点**`，每个分析节最多保留两处加粗。显示时将“基期”等术语换成直白表达；原始报告与统计数值不变，旧缓存无需重新生成。后续AI报告也会收到相同的阅读风格提示。

## 口径与限制

- 金额全程使用整数分；不修改账目，不自动纠错或重分类。
- 文件日期优先使用有效的 frontmatter `date`，缺失或异常时回退到文件名日期，同时显示诊断。
- frontmatter `date` 支持 `YYYY-MM-DD` 和 Obsidian 常见的 ISO 日期时间；日期时间按其中明确写出的日历日期归档，不进行时区换日。
- 只解析“今日消费记录”标题后的列表项，直到下一个标题；空白列表项被安全忽略。
- 无法解析的非空记录、日期异常以及正文与 frontmatter `total` 不一致都会显示文件、行号（适用时）和原因。
- 自定义比较按用户选择的完整区间；当前月与上月默认按截至今天的同期天数比较。
- 对比基期为零且本期非零时显示“新增”，两期均为零时显示“—”，不会输出无穷大百分比。
- 原始笔记定位会尝试跳到对应行；Obsidian 不同版本或移动端可能只保证打开文件。
- 图表为本地原生 SVG，不依赖 CDN、远程字体或外部服务。
- Vault API 的新增、修改、删除和重命名事件只重算受影响文件；修改记账文件夹或手动刷新时才重新扫描。
- 已完成桌面端和移动端模拟/窄屏验证；真实手机设备尚未验证。

## 隐私与兼容性

插件默认不访问网络，也不使用 CDN、远程字体、Node `fs`、Electron 或绝对 Windows 路径。只有用户主动配置的 Bark 提醒和 AI 财务判断会访问相应地址。API Key、Bark 地址和每日 AI 缓存保存在插件本地 `data.json` 中，该文件已被 Git 忽略；AI 请求不发送账本文件、文件路径或完整原始行，但会发送与异常候选直接相关、数量受限的交易日期、分类、金额和备注。`manifest.json` 设置 `isDesktopOnly: false`，界面使用 Obsidian 原生主题变量、触摸尺寸控件和窄屏单列/卡片布局。
