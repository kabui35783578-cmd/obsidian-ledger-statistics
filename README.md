# 记账统计

本插件只读取指定文件夹中的每日记账 Markdown，正文逐笔记录是唯一统计来源；frontmatter `total` 只参与核对，`.base` 与 `.duowei` 不会计入。

## 安装与使用

当前目录已经是可安装的 Obsidian 插件目录。构建后确保 `main.js`、`manifest.json`、`styles.css` 位于 `.obsidian/plugins/ledger-statistics/`，然后在“设置 → 第三方插件”中启用“记账统计”。使用左侧栏饼图图标或命令“打开记账统计”进入。

也可以从 GitHub Releases 下载最新的 `ledger-statistics-v*.zip`，解压到 Vault 的 `.obsidian/plugins/ledger-statistics/` 目录后启用插件。

默认打开总览；可在设置中选择首次打开时使用今天、本周、本月、工资日或今年。顶部筛选在六个视图间保留；本周按周一开始，当前周截止今天。工资日按每月15日至下月14日计算，当前周期截止今天。时间选择器旁的两个图标按钮会按照当前时间类型切换日期、周、月、工资周期或年份；自定义期间不启用周期切换。点击指标、图表、分类行或日期会进入对应明细。默认“消费支出”会排除设置中配置的 `债务/还款`，切换到“全部支出”可纳入。排除后的结果只是配置口径，并不代表已经人工核实的真实消费额。日均的分母是所选范围内实际存在日记账文件的日期数，缺少文件的日期不按零消费处理；有文件但当前口径金额为零的日期仍进入分母。

设置中的“每日预算”用于总览的“今日预算”液体进度条。预算卡片固定统计本地今天的支出，不受总览的日期、分类和关键词筛选影响；“预算分类”默认统计全部分类，包括 `债务/还款`，选择具体分类后只统计该分类。“今日预算星标口径”可以选择包含或排除星标支出，并统一作用于今日已花、当前工资周期支出和 Bark 提醒。预算金额下方会按31天估算月支出，并显示从本月15日至今天的当前工资周期支出；预算未设置时显示提示，超出预算时显示超支金额。填写“Bark 推送地址”后，当前预算口径首次达到或超过预算时会发送一次提醒，每个自然日最多一次；地址只保存在本地设置中。

总览顶部的“洞察”使用设置中的“每个工资周期到账工资”，以工资减去本工资周期的全部支出得到当前余额。程序会把当前周期进度与前两个完整工资周期的相同进度比较，扫描全部消费分类并生成工资压力、金额异常、消费频率、笔均金额、大额单笔和消费结构变化等候选事件。分类参考余量来自可用完整周期的平均值，只用于参照，不等同于预算。

洞察将未记账日期按零消费参与统计，今天未创建账本不会让洞察或周期末参考停止显示；补记后自动重算并使旧 AI 缓存失效。此规则适用于当前工资周期，以及最早已知记账日期之后的历史日期，不把开始记账以前的月份虚构成完整零消费周期。已有文件解析失败、日期或总额核对异常时仍需核对，不会用零消费覆盖错误。只有一个可用历史周期时只使用该周期，不除以二；不足两个历史周期或当前周期存在异常账本时暂停消费异常比较。周期末参考采用“本周期已花＋历史周期相同已过天数之后的平均支出”，周期初七天内或仅一个历史周期时标注低置信度；没有完整历史或当前账目核验失败时不显示预测。此方法不会将月初固定支出按日均倍增，但付款日期变化仍会影响参考值。点击 AI 判断卡片右上角的圆形感叹号，可查看判断依据、固定支出与统计口径，并打开异常账本；再次点击或按 Esc 收起。本次变更只调整洞察口径，不改变其他统计页明确标注的“有日记账文件日期”日均分母。

AI 缓存会核对统计快照；账目、工资或数据完整性变化后，显示“判断待更新”及上次生成时间，回退到最新本地判断，等待手动刷新。不会因当天每次记账而自动请求 AI。手动刷新只更新洞察区域，不重建其他卡片或重播入场动画；请求失败后持续显示原因，有效的上次结果仍会保留。移动端周期末参考金额保持完整显示，计算说明独占第二行。

星标使用交易内容及重复次数关联，插入空行或其他交易不会转移星标，插件运行期间重命名文件或文件夹会同步关联。升级时按当前账本迁移旧行号星标；无法找到的旧关联保留为未解析状态。修改被标记交易的金额、时间、分类、备注，或改变完全相同记录的数量后，需要通过“核对星标”重新关联，以免关联到错误记录。旧版已经发生的星标错位无法自动还原；插件未运行期间重命名文件也需要手动核对关联。

“AI 财务判断”是可选功能。启用后填写兼容 OpenAI Chat Completions 的接口地址、模型名称和 API Key。程序先计算周期汇总、分类参考、候选事件和共享证据目录，AI 再选择最值得关注的一项，从异常结果推测一至两个可能的生活场景、使用行为或消费行为原因，并生成针对原因假设的行动建议及最多三个相关分类意见。原因必须明确表达不确定性；交易备注已经说明用途时，不会再要求核实用途或判定固定、偶发。涉及季节的推断会收到按当前周期日期动态生成的月份和北半球常规季节，只用于排除明显时间错位，不代表具体地区天气。每条 AI 判断必须引用程序提供的有效证据；多个候选共享同一证据时只发送一次并通过 ID 引用，避免重复发送和重复放大。同一分类的相关变化会归入同组理解。具体金额、日期、阿拉伯数字和百分比仍由程序展示，AI 文案不得自行添加。为帮助 AI 区分一次性支出、重复购买和消费用途，插件只会为相关异常候选发送有限交易样本：单笔异常发送该笔备注，分类异常最多发送三至五笔代表交易，工资压力最多发送三笔主要支出；不发送账本文件、文件路径或完整原始行。备注被明确标记为不可信账目数据，只能作为用途线索，不能作为模型指令。返回无效、请求失败或功能未配置时，卡片继续显示本地候选结果；账目没有变化时手动刷新不会重复请求。MiMo 请求关闭不必要的深度思考，AI 请求最长等待 60 秒；超时或关闭页面后废弃结果，关闭前尚未发出的请求会取消。Obsidian 原生请求无法强制中断，因此连接尚未结束时保持请求锁，防止再次点击产生重叠请求；连接结束后可重试。

插件开启时，预算提醒随账目更新、设置变化及定时检查运行，无须打开总览。Bark 仅在 HTTP 成功且返回 `code: 200`、`message: success` 后记为当天已提醒；失败会留出五分钟重试间隔。Obsidian 被关闭或手机系统挂起期间不保证后台运行。回到前台及跨日检查会更新当前日期预设；手动选择的历史范围与自定义范围保持不变。账目读取使用文件版本检查及有上限的并发，整文件夹移动和删除会更新子文件缓存，迟到的旧读取不会覆盖新记录。

总览底部会显示“星标大额支出”面板。它不会自动按金额判断，而是汇总顶部所选时间范围内、由你在明细中手动标记为星标的记录；桌面端可右键记录，移动端可长按记录，在菜单中选择“标记为星标”。星标状态保存在插件本地设置中，不会修改原始 Markdown 账目。

## 洞察与固定支出确认

- 工资日固定每月 15 日。工资余额仅为到账工资减本周期全部账目支出，不等于银行实际余额。
- 同一工资周期内，已经展示过的候选提醒次日收进“已提醒事项”。金额影响增加至少 20% 且不少于 50 元时再次提醒；消费频次增加至少 3 次、客单价增加至少 10 元（两者还需增加至少 20%）、分类占比增加至少 10 个百分点且增加至少 20% 时也会重新提醒。工资超支风险不静默。当天重复打开保持稳定，历史最多保存 200 条事件标识和指标，不含原始消费备注。
- 本地程序负责金额、周期、候选事件和证据；AI 负责从已确认的异常结果推测可能原因并给出克制、可验证的建议。原因假设不等于事实，具体数字始终由程序展示，AI 不得编造财务事实。
- 设置 → 固定支出 → 管理固定支出：填写名称、预计金额，并确认本周期以及前两个周期是否支付。已支付须关联实际账目；本周期未支付可选择“尚未支付”，没有该项支出需明确选“此周期无需支付”。每笔账目只能用于一个固定项目，分期请拆项。未填写名称或金额的草稿不参与计算。
- 调整后周期末参考＝本周期已花＋历史剩余阶段平均（减去其中明确关联的固定项）＋本周期确认未支付的固定项。原始账目和实际余额不会因规则而改变；只有完整历史周期参与平均。支付状态未知、关联失效或重复使用账目时暂停预测并提示核对。进入新工资周期后需重新确认，不擅自假定已付或未付。
- 设置中的“测试 AI 连接”只发送简短测试消息，区分认证、接口/模型、限额、网络和超时问题；可能产生少量模型费用，与正式判断共享请求锁。
- 失效星标会出现核对提示；可在提示或设置中重新关联账目、移除单个星标，不修改源笔记。

## Lieflat Charts 视觉体系

界面采用纸张灰、墨黑与七级灰阶构成的单色系统，保留宽圆角卡片、细线图形、结论式标题和明确来源行。分类条形图、环形图、趋势折线/面积图和对比图分别基于 Lieflat Charts 的 F5、F4、F2/F3、F12 图形语法实现，并针对 Obsidian 的点击下钻、中文标签、深色主题和移动端触摸操作进行了适配。所有图形均由插件本地生成 SVG，不加载 Lieflat 页面或任何远程资源。

## 移动端

- 筛选区默认收起为一行摘要，点击后展开；当前日期、口径和分类无需展开即可确认。
- 开始与结束日期合并在同一个双列日期组中，六个视图入口保持单行可见。
- 总览指标使用 2×2 卡片布局；分类刻线、趋势图和期间对比使用独立的移动端图形，不再按比例缩小桌面 SVG。
- 较长趋势图支持横向触摸滚动，明细使用卡片列表，日历使用逐日单列列表。
- 所有主要控件保持至少 44px 的触摸高度；手机端不依赖悬停交互。
- 从图表、分类或日历下钻到明细时会保留原筛选条件；点击明细顶部的“返回上一级”即可回到原本月或原期间。
- 明细卡片的“打开来源”固定在卡片底部操作区，避免与备注内容混排。
- 移动端滑到底后停留；从底部重新上拉时显示进度，拉动约 100px 后提示“松手切换”。松手才进入下一个视图，未达到阈值或收回手势则回弹取消。最后一个视图不循环跳转。


## 口径与限制

- 金额全程使用整数分；不修改账目，不自动纠错或重分类。
- 文件日期优先使用有效的 frontmatter `date`，缺失或异常时回退到文件名日期，同时显示诊断。
- frontmatter `date` 支持 `YYYY-MM-DD` 和 Obsidian 常见的 ISO 日期时间；日期时间按其中明确写出的日历日期归档，不进行时区换日。
- 只解析“今日消费记录”标题后的列表项，直到下一个标题；空白列表项被安全忽略。
- 无法解析的非空记录、日期异常以及正文与 frontmatter `total` 不一致都会显示文件、行号（适用时）和原因。
- 自定义比较按用户选择的完整区间；当前月与上月默认按截至今天的同期天数比较。
- 对比基期为零且本期非零时显示“新增”，两期均为零时显示“—”，不会输出无穷大百分比。
- 原始笔记定位会尝试跳到对应行；Obsidian 不同版本或移动端可能只保证打开文件。
- 图表为本地原生 SVG，不依赖 CDN、远程字体或外部服务。
- Vault API 的新增、修改、删除和重命名事件只重算受影响文件；修改记账文件夹或手动刷新时才重新扫描。
- 已完成桌面端和移动端模拟/窄屏验证；真实手机设备尚未验证。

## 隐私与兼容性

插件默认不访问网络，也不使用 CDN、远程字体、Node `fs`、Electron 或绝对 Windows 路径。只有用户主动配置的 Bark 提醒和 AI 财务判断会访问相应地址。API Key、Bark 地址和每日 AI 缓存保存在插件本地 `data.json` 中，该文件已被 Git 忽略；AI 请求不发送账本文件、文件路径或完整原始行，但会发送与异常候选直接相关、数量受限的交易日期、分类、金额和备注。`manifest.json` 设置 `isDesktopOnly: false`，界面使用 Obsidian 原生主题变量、触摸尺寸控件和窄屏单列/卡片布局。
